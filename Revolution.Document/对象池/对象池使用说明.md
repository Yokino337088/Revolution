## 〇、它是干什么的

*先花 30 秒建立直觉，再动手写。*

> [!TIP]
> **只学 2 个东西就能干活（真的）**
>
> var bullet = RevPool.Get<Bullet>(bulletRoot);   // ① 取一个（预制体路径写在 Bullet 类的 [RevPoolPrefab] 特性上）
> // …用一段时间（飞出屏幕 / 打中目标）…
> RevPool.Return(bullet);                          // ② 还回去
> `Get` 会自动带上**资源引用**（池端着，不会被卸载掉），还会把对象复位（位置/旋转/激活状态按池的规则处理）。  
>   
>  想"延迟还"（比如让死亡动画播完）：`RevPool.Return(go, delayFrames: 30)`。

> **人话** 对象池 = 对象不销毁、只"还回去"，下次同样的请求直接从池里拿。
> 它替你把三件事挡掉：频繁 `Instantiate/Destroy` 的 GC 与卡顿、资源的重复加载与提前卸载、对象数量失控（有上限与瘦身）。

| 它替你解决的问题 | 怎么做的 |
|---|---|
| 子弹/飘字满天飞，创建销毁太贵 | 从池里**复用**，不做 Instantiate/Destroy |
| 池里的对象导致资源卸不掉 | 池端着资源引用：销毁池时才放（不用你手动 Release） |
| 用完忘记复位，出现"幽灵对象" | 取出来时框架给你一份"干净"的对象（位置/旋转/激活按规则复位） |
| 池越攒越大吃内存 | 空闲上限 + `TrimAll(keepCount)` 主动瘦身 + `ApplyCapacityToAll(capacity)` 统一改上限 |
| 切场景后旧池还在 | `ClearAll()` / `ClearGroup(group)` / `DestroyAll()` |

## 一、3 分钟做一把子弹池

*准备：预制体放在资源根目录的 `Battle/Bullet/Bullet_Normal.prefab`，根节点上挂一个 `Bullet` 脚本。*


```csharp
// ⓪ 声明：把"预制体在哪"写在脚本自己身上（和 UI 面板的 [RevUIPanel] 是同一种写法）
[RevPoolPrefab("Battle/Bullet", "Bullet_Normal", Group = RevResGroup.Battle)]   // 名字省略 = 用类名 "Bullet"
public class Bullet : MonoBehaviour { /* … */ }

// ① 发射：取一个并放到枪口（只写类型，不再手填任何路径字符串）
void Fire()
{
    Bullet bullet = RevPool.Get<Bullet>(bulletRoot);
    bullet.transform.position = muzzle.position;
    bullet.transform.rotation = muzzle.rotation;
}

// ② 回收：撞到 / 飞出屏幕 / 生命周期结束 —— 任何"这个对象不要了"的地方
void OnBulletDead(GameObject bullet)
{
    RevPool.Return(bullet);                     // 立刻还（会复位）
    // RevPool.Return(bullet, delayFrames: 30);  // 或者：30 帧后再还（留给死亡特效播完）
}

// ③ 异步取（第一次还没加载完时不卡帧；真机首次加载/WebGL 上必须用它）
RevPool.GetAsync<Bullet>(bullet =>
{
    if (bullet == null) return;                     // 加载失败 / 没写特性：回调收到 null（Console 有明确报错）
    bullet.transform.position = muzzle.position;    // 回调里再用
}, bulletRoot);

// ④ 老写法仍可用：没有脚本的预制体 / 临时取一下，手填"根目录 + 资源名"
var go = RevPool.Get("Battle/Bullet", "Bullet_Normal", bulletRoot);
RevPool.GetAsync("Battle/Bullet", "Bullet_Normal", g => { /* … */ });

// ⑤ 也支持直接给预制体（预制体已经是字段/引用时）
var slot = RevPool.Get(itemSlotPrefab, container);
```

> [!NOTE]
> **就这样，没有初始化步骤 + 路径只写一次**
> 池是**按"目录 + 名字"自动创建**的：第一次 `Get` 时建、以后复用，不需要 `new` 任何池对象。
> `[RevPoolPrefab]` 把路径收敛到**脚本类上的一处声明**：取用的地方只写类型，不会再出现"这里写错一个字母"的问题。想要编译期保护，root 也可以写生成的 `RevResPath` 常量。
> 注意：特性**不继承**（子类要自己写）；类上忘了写时会报错并告诉你怎么加，同步 `Get` 返回 `null`、异步回调收到 `null`。

## 二、"我要做 X" 对照表（全部 API）

*入口统一是 `RevPool`（GameObject 池）。*

| 我想… | 这么写 |
|---|---|
| 取一个（**推荐**：按类型，路径在 `[RevPoolPrefab]` 上） | `RevPool.Get<Bullet>(parent)` |
| 取一个（按类型，可能还没加载完） | `RevPool.GetAsync<Bullet>(b => { }, parent)` |
| 取一个（按资源路径，手填） | `RevPool.Get(rootPath, resName, parent)` |
| 取一个（按已有预制体） | `RevPool.Get(prefab, parent)` |
| 取一个（按资源路径，可能还没加载完） | `RevPool.GetAsync(rootPath, resName, go => { }, parent)` |
| 还一个 | `RevPool.Return(item)` / `RevPool.Return(component)` |
| 延迟还（等动画/特效） | `RevPool.Return(item, delayFrames: 30)` |
| 清掉某个池的**空闲**对象 | `RevPool.Clear(rootPath, resName)`（返回清掉几个） |
| 清掉整组池的空闲对象 | `RevPool.ClearGroup(RevResGroup.UI)` |
| 清掉全部池的空闲对象 | `RevPool.ClearAll()`（切场景常用） |
| 彻底销毁某个池（连资源引用一起放） | `RevPool.DestroyPool(rootPath, resName)` / `DestroyPool(prefab)` |
| 彻底销毁所有池 | `RevPool.DestroyAll()`（回登录/大版本切换） |
| 统一改空闲上限 | `RevPool.ApplyCapacityToAll(64)` |
| 主动瘦身（每个池最多留 N 个） | `RevPool.TrimAll(keepCount)` |
| 看纯 C# 池的统计 / 池名清单 | `RevRefPool.GetGlobalStats()` · `RevRefPool.GetPoolNames()` |

> [!WARNING]
> **Clear 与 Destroy 的区别（最常问）**
> Clear
> Destroy
> 日常用 Clear，切大场景/回登录用 Destroy。

## 三、"还"与"回收"：什么时候做什么

*只要记住一条：**谁取谁还，别自己 Destroy。***

- **回收的时机**：
- **不要手动 Destroy**：DestroyPool
- **还回去别再引用**：delayFrames
- **切场景**：RevPool.ClearAll()ClearGroup
- **觉得内存高**：TrimAll(32)ApplyCapacityToAll
- **排查**：RevRefPool.GetPoolNames()GetGlobalStats()

> [!TIP]
> **为什么池里的对象不会被"资源卸载"干掉**
> 不用你为池里的对象写 Release

**✓ GameObject 池（`RevPool`）**

看得见的东西

**✓ 纯 C# 对象池（`RevPoolCore<T>`）**

> **怎么选**

## 五、新手最容易踩的 5 个坑

| 坑 | 正确做法 |
|---|---|
| ① 忘记 Return（对象越堆越多） | 每个 `Get` 都要有一条"逻辑结束 → Return"的路径；不确定就用 `delayFrames` 兜底 |
| ② 用 `Destroy(go)` 销毁池里的对象 | 用 `Return`；要销毁池用 `DestroyPool` |
| ③ Return 之后还继续用这个引用 | Return 后立刻把引用置空；需要"还用一会儿"就延迟还 |
| ④ 对象上的状态没清（列表项残留旧文字） | 在 `Get` 之后**总是**显式设置全部需要显示的内容，别依赖"上次的残留" |
| ⑤ 数组/列表字段没清（越积越多） | 对象复用时它自己的集合字段要自己清 —— 框架只复位 Transform/激活状态 |

> [!NOTE]
> **最贵的一课**
> 还了之后还拿着引用继续改
