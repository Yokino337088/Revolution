REVOLUTION FRAMEWORK · BOOTSTRAP

一键初始化 · 使用说明

在游戏启动入口调用一次 RevInitialize.Initialize()，统一装配资源加载策略；不必再记住直接调用 RevResBootstrap.Instance.Init()。

01最快接入：启动时调用一行

把初始化放在首个业务场景开始加载资源之前。推荐使用独立的 Boot 场景，在它的启动脚本 Awake 或 Start 中调用：

using UnityEngine;
using Revolution;

public sealed class GameBootstrap : MonoBehaviour
{
    private void Awake()
    {
        RevInitialize.Initialize();
    }
}
调用成功后资源加载策略已经注册。之后可正常使用 RevUI.Open、带资源路径的 RevPool.Get、RevDataLoad 等资源加载入口。

运行期间可通过 RevInitialize.IsInitialized 查询门面是否已完成初始化。当前门面是显式调用式，不会在进入 Play 时擅自启动；这样资源扩展和项目配置有机会先完成装配。

02初始化做了什么

业务启动入口→RevInitialize.Initialize()→RevResBootstrap.Init()→资源策略就绪
  • 初始化资源系统策略：编辑器默认注册工程资源直读策略；运行时按 AB / Resources 策略加载。
  • 在本次运行会话内保持幂等：重复调用直接返回，不会再次清缓存、取消在途加载或重建 AB Loader。
  • 初始化失败会记录异常并重新抛出；门面状态恢复为未完成，可修复问题后重试。
  • 关闭 Unity Domain Reload 时，门面会在新 Play 会话的 SubsystemRegistration 阶段重置状态，便于下一次启动重新初始化。
不要在运行过程中直接重复调用底层 InitRevResBootstrap.Instance.Init() 会取消异步资源请求、释放预加载并清空旧资源缓存。项目业务统一调用 RevInitialize.Initialize()；编辑器切换 AB 模式时框架内部会自行重建策略。

03有资源扩展时的初始化顺序

热更新等扩展可能需要在资源策略注册前安装 ResMap 或包路径钩子。门面提供了一个可选前置回调，用于先装配扩展，再初始化资源系统：

// 示例结构：先安装资源扩展，再由门面注册资源策略
RevInitialize.Initialize(() =>
{
    // 在这里调用当前已安装扩展提供的 Install / Configure 接口
    // 具体类型和调用方式以对应扩展包的使用说明为准
});

前置回调只在本会话第一次成功初始化时运行。普通项目不接扩展时，无需传回调。

切勿递归初始化不要在这个回调里再次调用 RevInitialize.Initialize() 或直接启动另一套资源策略；递归调用会明确抛出异常。

04哪些模块不需要放进一键 Init

一键门面只负责框架级必需装配，不会替项目决定业务配置。大多数模块已有自己的 Unity 生命周期钩子或按需创建逻辑：

模块 / 能力启动方式项目需要做什么
事件、输入、计时器、对象池、UI、场景状态等Unity Runtime 初始化钩子复位静态状态；驱动按需安装正常使用公开门面，不要重复清理或手动重复驱动
应用前后台生命周期框架在首场景前自动安装隐藏宿主按需订阅 RevAppLifecycle 事件
服务定位器由业务组合根注册并调用 Build()自行决定服务类型、作用域与释放时机；需要 RevITickable 时由自己的宿主逐帧调用 Tick()
GM 命令、事件监听、输入绑定等业务注册模块状态由钩子复位，业务注册表需按项目启动时机重新装配在自己的启动入口显式注册业务内容
服务定位器不会被自动 Build服务注册表属于业务组合根。框架无法猜测项目需要哪些服务，也不能统一替所有作用域调用 Tick 或 Dispose。

05常见问题

不调用会怎样？

依赖资源系统路径加载的 UI、数据表、音效或对象池预制体可能加载失败，因为资源策略尚未注册。直接传入已持有 prefab 引用的 RevPool.Get(prefab) 不走路径资源加载，是例外。

可以在多个场景的 Awake 都调用吗？

可以，门面在一个运行会话内只初始化一次。不过推荐仍集中在唯一的 Boot / Bootstrap 入口，方便保证所有场景使用资源前已完成初始化。

运行时修改了资源加载模式怎么办？

编辑器的 AB 模式切换会由资源系统内部重建策略。普通业务不要用 RevResBootstrap.Init() 手动重复切换。

接入失败先检查什么？

  1. 确认 RevInitialize.Initialize() 在第一次路径资源加载之前执行。
  2. 查看 Console 中的初始化异常和资源错误原因。
  3. 检查 AB 模式、资源映射表及资源根目录配置。
  4. 确认没有其他脚本在启动后直接重复调用 RevResBootstrap.Instance.Init()。
