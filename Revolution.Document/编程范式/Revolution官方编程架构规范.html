01 · 常用功能统一使用框架现有接口

项目仅实现自己的登录协议、玩家数据、关卡规则、流程转移与接线；不重造框架已有的加载、回收、派发或计时。业务不直接调用 Core/Implementation/Support 内核。示意业务接口不是框架 API。

需求框架现有入口项目责任
启动、场景切换RevInitialize、RevScene场景选择、失败回退
游戏阶段 / AIRevLightFSM / RevLightStackFSM / RevHeavyFSM状态、合法转移及宿主驱动
阶段生灭、无界面业务RevScope、RevDomain、RevLogicBase / RevLogic自定义域、状态回调开关域、局内业务
跨域共享能力RevServices；并行同类实例才用 RevServiceLocator.CreateScope()项目服务注册与注销
UI / 资源 / 池 / 表RevUI、RevResManager、RevPool、RevDataTableManager面板、数据、资源路径
时间 / 通知 / 每帧 / 异步 / 演出RevTimer、RevEvent、RevMono、RevTask、RevSequence事件语义、业务取消与演出
输入 / 音频 / 观察 / 测试RevInput、RevSound、RevLog、RevGM绑定、失败观察、受控测试命令
按生存期分工：仅当前屏幕的逻辑留在面板；没有界面、只活这段玩法域的业务用 [RevLogic(域名)] + RevLogicBase；跨域长期能力用服务。游戏域 RevScope 不等于服务容器的 CreateScope()。

02 · 登录 → 大厅 → 战斗 → 结算 → 退出：FSM + RevScope 统一调度

启动入口只装配框架和项目服务/GM 一次；一个项目流程控制者持有 FSM，所有切换请求经它验证。FSM 管现在在哪，域管这一段的对象怎么收。每个状态只开关自己的域；框架的 RevScope 不依赖 FSM，联动写在业务状态回调里。RevScene 负责载入 Unity 场景，但不替你切 FSM 或游戏域。

流程策略选型及转移
线性互斥阶段RevLightFSM<T>：旧状态 OnExit 关旧域，新状态 OnEnter 开新域；结算可拥有独立域，退出通过终止状态收尾。
大厅在战斗时保留RevLightStackFSM<T>：Push Lobby → Push Battle（Lobby OnSuspend 停 Tick）→ 按需 Push Settlement → Pop Settlement/Battle（Lobby OnResume）→ 登出 Clear 自顶向下退出域。

若结算仅是战斗结束时的一块 UI，可以仍归 Battle 域；若需自己的计时器、面板与卸载边界，用业务 GameDomain.Settlement。项目域定义成 const string；框架 RevDomain 仅预置 Global/Lobby/Battle，RevResGroup 是另一种资源分组枚举，勿为新增游戏域随意修改它。

状态与域必须遵守的契约

  1. OnEnter 调 RevScope.Enter 并保存句柄；返回 RevScopeHandle.Empty 时停止启动。域开放后启动归属的 RevLogic.Start<T>()，返回 null 需处理。
  2. OnExit 关自己保存的域句柄；关非栈顶域会先连关上方域。Logic Stop 先解绑事件、计时器、Mono、服务，资源仍需按租约与组契约释放。
  3. 栈状态 OnSuspend/OnResume 用 SetTickEnabled(false/true)。它仅控制域兜底每帧及 Logic Tick，不暂停计时器或显式 owner 的普通 Mono。
  4. TakeOverOwner 默认 true：未指 owner 的 Timer/Event/Mono 可由活动域兜底；显式 owner 优先。服务不自动归域，用 owner: RevScope.Current 或 Attach(owner)；跨域心跳用长期 owner。
  5. Reclaim 默认 Unknown：不做资源/池整组回收；配置非 Unknown 回收组后才有组兜底，取用/释放仍要配对；不要把共用组作为战斗组。
  6. 同名域默认拒绝重入；允许重入只是复用句柄。晚到回调核对原句柄 IsOpen、FSM 状态及取消令牌。
真实示例：Assets/Revolution.Demo/RevScope.Demo/RevScopeFlowDemo.cs 挂任意场景即可观察大厅→战斗→回大厅→退出、Logic 与回收报告；没有独立 Scope 场景。现有 Demo 按域名开关域，项目持有句柄是更精确的建议，不表示 Demo 已采用句柄版。详见作用域使用说明和状态机使用说明。

异步切换边界

RevLightFSM<T>.ChangeToAsync 准备期依次等待旧 PrepareExitAsync 和新 PrepareEnterAsync，交割时才走旧 OnExit → 新 OnEnter；其间旧状态仍可 Update。新请求可取消旧准备，await 返回后仍要检查 CurrentState。不在请求切换时抢先关旧域。栈机没有异步 Push/Pop；先业务侧准备，再同步操作栈。资源异步加载必须按 RevResManager 真实 API、句柄和 Release 契约，不照抄状态机源码里假设的 LoadAsync(..., token) 注释。

03 · 关键业务代码提供 GM 测试入口

GM 命令调用与玩家按钮/网络入口同一项业务服务或流程控制者，不直接改 UI 字段、FSM 私有表、资源内核、存档/服务器数据。每个关键阶段至少准备“查询快照 + 受控动作 + 非法动作有可读失败”；不把所有业务 public 方法无差别暴露。

  • 集中注册一次 RevGM.Register(完整分组名, 描述, handler, RevGMArg...)；RevGM.Execute 返回 RevGMResult.Success/Message/ElapsedMs，业务拒绝抛带原因的 RevGMUsageException。
  • [RevGMEntry] 只标静态无参、仅做注册的方法供编辑模式生成目录；不自动注册，不在注册方法外层读取服务或切场景。参数声明默认值与 args.Int/Float(..., fallback) 必须一致。
  • 正式环境不注册变更类测试命令或明确关闭；HighRisk 只是编辑器面板二次确认，直接 Execute 可绕过；Hidden 只隐藏联想，均非权限。

下列 IRevGameFlow / GameFlowGmCommands 是项目示例，不是框架已有 API；由项目实现前者的 FSM + Scope 接线，并在测试环境注册服务及命令：

using Revolution;

public interface IRevGameFlow
{
    string Snapshot();
    bool TryEnterBattle(out string reason);
}

public static class GameFlowGmCommands
{
    [RevGMEntry("游戏流程测试命令，只在开发测试环境注册")]
    public static void Register()
    {
        RevGM.Register("流程/快照", "读取当前流程与域状态", args =>
        {
            IRevGameFlow flow = RevServices.GetRequired<IRevGameFlow>();
            return flow.Snapshot();
        });
        RevGM.Register("流程/进入战斗", "从大厅进入战斗（测试环境）", args =>
        {
            IRevGameFlow flow = RevServices.GetRequired<IRevGameFlow>();
            if (!RevScope.IsActive(RevDomain.Lobby))
                throw new RevGMUsageException("大厅域未打开");
            if (!flow.TryEnterBattle(out string reason))
                throw new RevGMUsageException(reason);
            return flow.Snapshot();
        }, RevGMFlags.HighRisk);
    }
}

真实项目的 Boot 只在受控环境注册 IRevGameFlow 实现，再调用一次 GameFlowGmCommands.Register()。编目工具可在非 Play 时调用注册方法，但 handler 到运行时执行才访问服务。GM 状态查询、动作及拒绝场景见GM 使用说明。

04 · GM × MCP × AI 的自动验收约定

能力边界：Unity 工程声明了第三方 com.coplaydev.unity-mcp 包，但框架没有专用 GM→MCP 工具、已连通测试桥或自动调度器。编辑器 GM 面板仅 Play 时执行；运行时 RevGM 是供项目接控制台的后端，框架没有现成游戏包交互控制台。MCP 包存在 ≠ AI 已能执行 GM。

由项目方实现最小受控适配器：允许环境/身份校验 → 精确命令白名单及参数上限 → 主线程调用 RevGM.Execute → 回传 RevGMResult 和 FSM/Scope 前后快照 → 超时与审计 → 失败不盲重试。不得把任意代码/反射执行、ExitAll、强制卸组、删档或真实支付开放给 GM/MCP。HighRisk 不代表授权；日志/返回值不包含凭据与玩家隐私。

标准步骤必须断言的证据
启动/登录登录结果与 Lobby 状态一致；域不重复打开，失败有具体原因
大厅→战斗GM Success、FSM 状态及 Lobby/Battle 域一致；栈式大厅保留且 Tick 暂停
战斗→结算结果由业务服务产生；战斗结束与结算域生命周期符合策略；无新增残留
结算→大厅/退出回收报告判空后检查错误与扫尾，Logic 数/域栈回基线
非法转移失败带原因，FSM/域/资源状态没有部分修改
异步取消/切场景没有抢先关旧域或在失效域写数据；场景与流程状态对齐

保存环境/版本、输入命令、Success/Message、前后状态、回收报告、异常日志、断言结果。命令可注册不等于测试已通过；离线纯 C# 断言也不能证明 Unity PlayMode、真机、AB 加载或 MCP 连通。网络、音频、图形等另做集成或设备测试。

05 · 新业务模块交付检查

  1. 画出 Login/Lobby/Battle/Settlement/Exit 状态图，明确大厅是否保留、每态域/资源组、非法转移及取消去向；一个流程控制者驱动 FSM。
  2. 先选用现有门面；各 Timer/Event/Mono/服务/资源句柄都标明生存期及清理者；域服务显式归属，Logic 不替代所有资源 Release。
  3. 给关键路径留可查询、可触发、可验证拒绝的 GM 命令；真实权限、白名单和环境由项目控制，不能靠编辑器 HighRisk。
  4. 编译并跑相应流程 Demo/GM，查域关闭报告、重进 Play、异步取消；AB/热更/移动端另跑目标平台，记录实际结果与未执行项。
  5. 行为改动同步模块说明和业务测试证据；不要把技术方案、示例接口或尚未接通的 MCP 当成框架现成能力。
这是一套游戏业务编程约定：项目实现业务规则与安全接线，不新增第二套框架，不宣称已有真实登录、业务 GM 命令或现成 AI 自动测试流水线。

06 · 服务注册：接口做键还是类做键

RevServices.Register<TService, TImpl>() 的两个泛型参数分别是取用键与实现类，不是固定的「接口 + 实现」：TService 是调用方 GetRequired<TService>() 用的键；TImpl 是容器真正 new 的类型，框架约束为 TImpl : class, TService, new()。因此 Register<X, X>() 是合法的“自注册”，唯一含义是让容器创建并按规定释放。

重载谁创建注销时处置适用
Register<TService, TImpl>()容器（需公开无参构造）容器创建的实例会 Dispose实现 IDisposable、需要收尾
Register<TService>(instance)调用方只摘表，不 Dispose外部已托管实例
Register<TService>(factory)工厂会 Dispose需要构造参数

判据：按“以后会不会换实现”选。

条件选择例子
多份实现 / 单测要替换 / 只暴露能力接口做键Register<IBattleService, BattleService>()、Register<IScoreProgress, ScoreProgressStore>()
只有一份实现，且调用方要用具体成员类做键Register<StoryProgress, StoryProgress>()、Register<GameAudioSettings, GameAudioSettings>()
接口没有成员，或只有 Dispose不要抽，直接用类—
两种都合规；不合规的是同一入口里风格混用却没有说明。出现两种写法时，在注册处用一行注释写明理由（示例见 RevGame GameBootstrap）。
Register<TService, TImpl>() 是懒创建：不调用一次 GetRequired 就不会执行构造函数；依赖构造函数完成订阅或初始化的服务（图集回调、音量应用），必须在注册后立即取一次。owner 只解决“谁负责注销”，不等于“随域回收”。
