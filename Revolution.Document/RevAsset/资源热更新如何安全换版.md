# 资源热更新如何安全换版

活动页刚下载完新素材，玩家还在看上一版的大厅。如果立刻删掉老包，旧页面可能在返回时丢贴图。如果等下次启动再重下一整套，又浪费玩家的时间和流量。**RevAsset 把下载、安装和换版分成三个检查点。运行中的页面用完旧资源后，下一轮才切到新版本。**

## 📦 把同一个材质装进哪只包

AB（AssetBundle，Unity 把图片、声音、预制体等装起来的原生资源包）仍由 Unity 构建。试验里，两个预制体分别打包，却引用了同一个材质。采集器先算出谁用了它，给材质安排一份共享归属。Unity 构建完成以后，再读取实际依赖清单，确认两个包确实指向同一个持有者。一个文件可以用目录规则，也可以被单独一条更具体的规则接管。已有 Unity 包名和变体也可以继续参与。 [Unity 原生构建接口](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/BuildPipeline.BuildAssetBundles.html) · [采集和归属实现](../../RevolutionFrameWork_Unity/Assets/Revolution.RevAsset/Editor/RevAssetCollector.cs)

逻辑地址（业务用来点名的路径）交给框架已有的索引。打开页面、场景预热和域退出都沿用同一套租约（谁还在用资源的记录）。包的来源跟随生效版本，已经取得的包引用由该版本的加载器回收。**这个接法让项目在面板切换资源后端后，可以沿用已有的业务加载代码。** [框架装配](../../RevolutionFrameWork_Unity/Assets/Revolution/Runtime/RevResourceSystem/Support/RevResBootstrap.cs)

## 🔏 看见下载完成之后还要检查什么

1. 从频道读取一个很小的发布指针。它指定应用兼容代号、平台和清单摘要。RSA 签名用客户端持有的公钥检查，确认指针来自有发布权的人。
2. 按 SHA-256（文件内容的指纹）计算缺失对象。相同文件直接复用。剩余包写入同卷临时文件，续传时核对服务器返回的起点和总长。
3. 包长度、内容指纹和依赖都对上后，写入新的安装记录。文件和清单全都就绪后才替换当前记录，前一版仍可用于回退。
4. 页面或场景完成交接，全局缓存里没有活跃租约和在途请求，框架才可装配新目录。下次启动也会自动选择完整安装的版本。

初始化和现有包的切换只有一个入口。选中 RevAsset 后，旧资源策略照常归还自己的引用，新请求再从新版本取货。若网络上发布了一个错误版本，把旧内容按更高发布序号重发，可以走常规的完整性检查。 [签名验证](../../RevolutionFrameWork_Unity/Assets/Revolution.RevAsset/Runtime/RevAssetRelease.cs) · [安装与回退](../../RevolutionFrameWork_Unity/Assets/Revolution.RevAsset/Runtime/RevAssetStore.cs)

## 🧪 五个真实包的回归

2026-11-24 在 Windows 的 Unity 2022.3.15f1c1 上使用原生 Windows AB。测试目录包含两份文本、两个预制体和它们共享的材质。第二版只修改一份文本。HTTP 服务器在本机提供静态文件，并在续传请求返回实际 Range 区间。这里量的是此次固定负载传了多少字节，以及失败和回退走到了哪一步。

| 动作 | 实际回执 |
| --- | --- |
| 扫描和构建第一版 | 4 个逻辑地址、5 个原生包、1 份共享材质 |
| 修改一处文本并安装第二版 | 4 个对象直接复用，1 个对象下载 |
| 从变更包的中间继续 | 1,211 B 的资源文件，本次 HTTP 续传 606 B |
| 改写签发版本字段 | 指针签名不通过，第一版继续使用 |
| 损坏同样大小的变更包 | 内容指纹不通过，安装指针保留第一版 |
| 持有旧版文本和预制体时切换 | 换版被拒绝，预制体仍可读到共享材质 |
| 关域、切换、回滚 | 旧租约归零，读到第二版，再读回第一版 |

✅ 使用同一批首包构建了独立 Windows Mono Player。Unity 只为该平台注入了 5 个原生包。启动独立进程后实际通过 RevAsset 挂载第一版，用同一个资源门面加载文本并退出。

实测还抓到了可移植性问题。Unity Mono 的默认 RSA 工厂在本机生成的密钥达不到配置要求。编辑器改用明确生成并核验模数长度的发布工具。Windows 上长缓存路径叠加摘要和临时文件名也会触发写入失败。缓存身份及同卷临时名称改用短文件名，原子替换仍发生在同一个目录。

## 这些设计如何对齐成熟方案

采集、可定制分包、按标签选择下载和运行模式参考 YooAsset。Unity AssetGraph 提供了构建工具把预览与实际产物分开的参考。xasset 提供本地迭代与发行路径并存的参考。它们是行为对照，RevAsset 使用自己的目录、安装记录和框架后端契约。 [YooAsset](https://github.com/tuyoogame/YooAsset) · [Unity AssetGraph](https://github.com/Unity-Technologies/AssetGraph) · [xasset](https://github.com/xasset/xasset)

RevAsset 目前验证了原生包、工程导入、域内释放、差量安装和回退。上表是 RevAsset 的端到端证据。与其他方案比较包体或运行耗时，应使用同素材、同 Unity 版本、同压缩选项和同冷暖状态运行两套产物。安卓和浏览器应在各自目标完成部署验证。 [安装与操作](../../RevolutionFrameWork_Unity/Assets/Revolution.RevAsset/README.md) · [开发 Skill](../../Skills/revolution-revasset/SKILL.md)
