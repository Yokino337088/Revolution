# RevMCP 内存通道与临时文件清理

## 运行过程

日常 RevCLI 和 RevMCP 查询领到终态就确认，Editor 释放响应，只保留有期限的去重身份。断线后查询原工单。旧版文件桥和批处理使用临时工单，读取回执和必要的诊断后立即永久删除。

| 临时文件 | 谁负责清理 |
| --- | --- |
| 场景与游戏截图 | RevCLI 和 RevMCP 在读取 PNG 后删除，独立 Player 在 HTTP 传输结束后删除。用户需要留图时使用显式导出。 |
| Test Runner 和旧 scenario | 调用端先消费终态和用户指定的报告，然后删除临时结果、标记和逐轮记录。取消等待的测试可用 `test.result` 领取终态。 |
| 旧文件桥和后台工单 | 领取终态后删除文件。批处理失败会附上日志尾部，随后删除临时日志。 |
| 活动事件 | 只有 RevMCP 窗口开启才创建。窗口读取后逐个删除，关闭时清掉待消费事件并停止采集。最多暂存 64 个事件，总计不超过 4 MiB。 |

AI 使用内联计划或标准输入。临时输入由创建者在 `finally` 删除。报告和长久证据导出到明确指定的文档目录，避开 Unity 的 `Library/RevolutionAutomation/jobs`、`activity`、`screenshots` 与工具的 `results`。

## 清理历史遗留

`storage.status` 查看工单、后台凭条、旧截图、待领取截图和旧活动分段。 `storage.prune` 默认预览，传 `dryRun=false` 才执行。升级后自动回收原先已停用的活动分段和过期工单。正在执行的请求、尚在领取窗口内的文件、`.keep`、自定义工单文件和链接会受到保护。兼容旧版本的天数和容量设置用于异常退出补偿，正常消费完成时即时清理。

更新 Unity 桥、RevCLI 和 RevMCP 到同一版本后重启常驻 RevMCP。配置与连接心跳在 `Library/RevolutionAutomation` 根目录，凭据只在本机使用。

## RevGame 验证

在 Unity 2022.3.15f1c1 的 RevGame 工程实测场景截图、Play 内截图、运行时 HTTP 截图、后台回执领取和旧 scenario。实时活动窗口仍能看到 Agent 和 Unity 的执行结果。领取后，工单、活动、截图和后台凭条目录的文件数均为 0。

用过期工单、活动分段、截图和后台凭条验证预览与回收，并核对带 `.keep` 的工单、自定义文件和期限内的凭条可以正常保留。
