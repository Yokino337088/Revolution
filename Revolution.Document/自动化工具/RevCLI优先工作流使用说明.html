二调用时间

常驻服务 + 快速路径：启动一次，之后每条命令只做一次本机转发。

做了什么

  1. 常驻服务：daemon start 起本机后台进程，之后每条命令只做一次 HTTP 转发。服务端复用 argparse 解析器和与 Unity 的连接。
  2. 快速路径：rev.py 在导入 argparse 与整个 cli 模块之前先判断能否转发，常驻服务在运行时跳过约 200ms 的导入。判断不确定时（未知选项、--help、本地专属命令）原样走完整 CLI，语义不变。
  3. 不转发的命令：daemon、doctor、gif、evidence、editor launch、pipeline --validate 和 --mode batch，避免常驻服务成为 Unity 的父进程或抢工程锁。

实测

同一工程、只读 editor.status、15 轮交替取样。

方式中位数P95
无常驻：python rev.py --no-daemon329 ms406 ms
常驻 + 快速路径：python rev.py201 ms434 ms
常驻 + rev.cmd390 ms608 ms
常驻 + py -3.13 启动器278 ms853 ms
直连 curl.exe → /call（不起 Python）130 ms270 ms
不要用 rev.cmd 或 py 启动器两者分别多出约 190ms 和 77ms 的壳启动成本，比无常驻的直调还慢。直接用解释器路径调用 python rev.py。数字来自本机一次测量，换机器或 Unity 负载会变。

多步操作合并成一次往返

方式适用说明
call batch.call互不依赖的同步动作一次最多 64 步，默认遇错即停。实测 10 步约 111ms，拆成 10 次约 994ms
pipeline <文件>有顺序依赖、需要引用前一步结果或 finally 清理失败后仍执行 finally

batch.call 不接受 Play、编译、构建、测试和 gm.*/ui.dump 等依赖帧推进的动作。

三使用流程

每个工作会话启动一次常驻服务。

$py   = '<Python 解释器路径>'      # py -3.13 -c "import sys;print(sys.executable)"
$rev  = 'Revolution.RevCLI/rev.py'
$proj = '<Unity 工程绝对路径>'

& $py $rev --project $proj connect                    # 含打开 Unity 和 daemon start；可重复执行
& $py $rev --project $proj --mode live editor status  # 之后都走常驻服务
& $py $rev --project $proj daemon status
& $py $rev --project $proj daemon stop
  • 始终显式传 --project。已有 Unity 编辑器在运行时只用 --mode live，不另开 batch。
  • 参数含中文或复杂对象时用 call <动作> --json <文件>，避免 PowerShell 转义破坏数据。
  • 常驻服务发现 CLI 代码或清单更新后会自动退出，该次调用转本地执行，再跑一次 connect 即可。改了 Unity 桥后 editor wait 等编译完成。
  • 没有启动常驻服务时命令仍可用，只是每次多付约 130ms。

四新增的制作能力

UI 面板与 Prefab 全流程。

UI 面板

动作参数要点
ui.createkind（Canvas/EventSystem/Panel/Image/RawImage/Text/Button/Toggle/Slider/Scrollbar/Dropdown/InputField/ScrollView）、name、parent、scene除 Canvas、EventSystem 外必须在 Canvas 之下；Text 是内置 UnityEngine.UI.Text；支持 Undo
rect.getid 或 objectPath、scene返回锚点、轴心、位置、尺寸、偏移、本地矩形、所属 Canvas
rect.set同上，加 anchorMin/anchorMax/pivot/anchoredPosition/sizeDelta/offsetMin/offsetMaxoffsetMin/offsetMax 与 anchoredPosition/sizeDelta 二选一；只写给出的字段
单独改锚点会让矩形位置变化要保持位置，同时给出偏移。

Prefab

动作说明
prefab.create场景对象保存为新 Prefab，不覆盖已有资产
prefab.instantiate实例化到指定场景和父节点
prefab.inspect / prefab.modify不打开窗口，直接读写子节点或组件属性并保存
prefab.apply把实例的全部覆盖写回 Prefab 资产并保存。只允许 Assets 下的 Prefab；写盘不可 Undo
prefab.unpack解除实例与资产的关联，不可 Undo。unpackMode=root（默认，仅最外层）或 completely（含嵌套）
不可撤销prefab.apply 和 prefab.unpack 调用前确认用户授权。

示例：带按钮的面板存成 Prefab

& $py $rev --project $proj --mode live ui create --kind Canvas --name MainCanvas
& $py $rev --project $proj --mode live ui create --kind Panel  --name Panel --parent <Canvas 的 id>
& $py $rev --project $proj --mode live ui create --kind Button --name BtnOk --parent <Panel 的 id>
& $py $rev --project $proj --mode live rect set --id <Panel 的 id> --set anchorMin=[0,0] --set anchorMax=[1,1] --set offsetMin=[0,0] --set offsetMax=[0,0]
& $py $rev --project $proj --mode live rect get --id <Panel 的 id>
& $py $rev --project $proj --mode live prefab create --id <Panel 的 id> --path Assets/UI/Panel.prefab

对象 id 来自上一条命令的返回，只在当次域有效；域重载后重新获取。

五给 AI 的路由规则

对应 Skills/revolution-unity-editor。

  • 先用 commands --action <动作> 或 commands --live 查真实契约，再调用。
  • 修改前先 inspect/get，修改后用同一查询读回断言。
  • 编译、测试和构建用显式等待：editor.wait、test.result、build.player 的真实 BuildReport。
  • Play 中调 GM 用 runtime start + game gm；需要一份计划带断言并自动出报告时，可选 RevMCP（rev_run）。
  • CLI 与 MCP 共用同一个 Unity 桥和同一份参数契约。

七边界

  • 不提供任意 C# 或 shell 执行。
  • batch.call 不能包含 Play、编译、构建、测试和运行时动作。
  • 常驻服务只监听本机，请求带令牌头，空闲超时自动退出。
  • 清单里存在的动作不等于旧编辑器已安装；以目标工程的 commands --live 为准。
