〇先用一句话

先配常驻 RevMCP，让 AI 查询真实接口；CLI 命令是 AI/CI 参考，不是新手作业。

搭建场景“在指定场景里创建 Cube，设置世界位置和局部缩放，读回确认正确。不要覆盖我的场景，临时对象做完清理。”
调整材质“查这份材质真实 Shader 属性，克隆一份再改颜色；保留原件和 GUID，给我读回结果及实际画面。不存在的属性请明确报错。”

这两件事都走 Unity 正常 API、Undo/Prefab 规则与资产保存链，不是改 YAML，也不是让 AI 随意执行 C#。

不是推倒旧工具。原有编辑器、游戏、资源与测试入口保留，再补高频缺项。

二原始体与三维变换

不再让 AI 猜 m_LocalPosition 等序列化字段，直接表达 Unity 坐标语义。

动作参数结果 / 拒绝边界
gameobject.primitivetype、name；可选 parent、sceneCube/Sphere/Capsule/Cylinder/Plane/Quad 六种公开名称；真实 Mesh/Renderer/Collider、Undo。父节点与场景不一致、非法类型或缺名字先拒绝。
transform.getid 或 objectPath；可选 scene世界/局部位置、Euler、Quaternion、局部缩放、lossyScale、父节点和目标身份。
transform.setid/objectPath/scene、space、position、eulerAngles、localScalespace=local/world；position/eulerAngles 三项有限数字；localScale 始终局部。所有参数预检，支持 Undo、Prefab override 和场景 dirty。
{
  "target": "editor",
  "action": "gameobject.primitive",
  "arguments": {"type": "Cube", "name": "PreviewCube"}
}
{
  "target": "editor",
  "action": "transform.set",
  "arguments": {
    "id": "<创建结果里的当次ID>",
    "space": "world",
    "position": [1, 2, 3],
    "eulerAngles": [0, 45, 0],
    "localScale": [1, 1, 1]
  }
}
局部缩放不等于世界缩放父节点有缩放时，世界位置需逆变换。零缩放父节点不可逆，直接拒绝；不靠写出 NaN 或“看起来差不多”完成操作。单次参数中有坏字段，不能先改其它字段。

根 Prefab 实例 Transform 的位置/旋转是 Unity 的默认 override。验收时要按该语义检查实际 PropertyModifications；排除默认 override 的查询不能证明修改没被记录。Undo 支持对象变换，但不代表磁盘资产创建可以撤销。

三Shader 和材质

先查声明，再按类型改。错误拼写、错误纹理或未知关键字不能把材质改到一半。

动作参数用途
shader.listquery、offset、limit（1..500）查询资产与当前已加载 Shader 名、路径、supported 与 findable。创建/切换材质选 findable=true；可见的编辑器私有名称不一定能被 Shader.Find 解析，不声称列全未加载内置 Shader。
material.inspectpathShader、类型化属性、关键字、renderQueue；只读 Assets/Packages 中现存 .mat。
material.createpath、shader按真实 Shader 名创建新的 .mat；父目录需存在，不覆盖。
material.clonepath、destination克隆到新 .mat，源资产与其 GUID 不变，不覆盖目标。
material.setpath；可选 shader、properties、renderQueue、enableKeywords、disableKeywords候选材质完整预检后修改原件并保存，支持 Undo，空修改拒绝。
Float / Range有限数字，Single 范围
IntInt32 整数，不接受小数或 bool
Color / Vector四项有限数字数组
Texture资产路径或 null，纹理维度须匹配
{
  "target": "editor",
  "action": "material.set",
  "arguments": {
    "path": "Assets/Materials/Preview.mat",
    "properties": {"_Color": [0.2, 0.6, 1.0, 1.0]},
    "renderQueue": -1
  }
}

例子只适用于声明了 _Color 的 Shader。实际属性名从 inspect 读取。renderQueue 为 -1..5000，-1 继承 Shader；关键字必须存在于该 Shader 的局部 keywordSpace，同一关键字不能同时启用和禁用。

不正确
逐个改源材质 → 最后才发现纹理类型错误 → 源件已部分污染；用 Renderer.material 无意克隆一堆材质。
当前做法
所有试写在候选副本 → 预检名称、类型、维度、关键字、队列及输出预算 → 一次提交源件 → 保存并读回。

材质创建/克隆是磁盘资产操作，不承诺 Undo；临时资产应通过已授权的 asset.delete 清理。Shader.isSupported 与属性读回不能替代目标平台编译或真实画面验证。

四AI 正确操作流程

省往返，不省身份、权限和后置验证。

记录现场→发现接口→查询预检→受控修改→读回 / 清理
  1. 明确 --project；记录 scene.list、dirty、Play、选择。不替换未保存场景，不改用户包源/编辑器版本。
  2. 新版 rev_discover 支持 target/query/offset/limit，旧版使用空参数。每次返回的对象 ID 有会话寿命，重载后重新查。
  3. 先 get/inspect 判断目标、类型、属性和可写性，再用精确参数操作。资产用相对 Assets 路径，禁止越界、目录链接写入和已有目标覆盖。
  4. 同步步骤可 batch；编译、Play、构建、测试及运行时跨帧保留顺序计划等待。失败不重放变更。
  5. 读回值、数量、身份、GUID、保存状态；实际测试加断言和 finally。临时件清理，永久编辑保留。
  6. 视觉要求交真实截图/动态 GIF。纯规则测试明确视觉未执行，不能把 transform.set 成功写成“画面正确”。

五CLI、MCP 与 Skill

同一 Unity 入口可以由 CLI 与 MCP 调用，复杂参数优先 JSON，别让 shell 改坏中文或数组。

从仓库根目录，供 AI/CI 使用：

python Revolution.RevCLI/rev.py --project RevolutionFrameWork_Unity --mode live call transform.set --json transform.json
python Revolution.RevMCP/rev_mcp.py --project RevolutionFrameWork_Unity call editor material.inspect --json material.json
python Revolution.RevMCP/rev_mcp.py --project RevolutionFrameWork_Unity --compact-tools serve

参数文件就是对应动作的 arguments 对象，不包外层 target/action。MCP 调用则使用上面的完整对象。

新增框架 Skill：Skills/revolution-unity-editor/。复制完整目录到项目 Agent 的 skills 目录，例如 .codebuddy/skills/ 或 .codex/skills/。它负责通用编辑器操作；玩法架构继续用 revolution-framework，游戏业务测试用 revolution-ai-automation，性能归因用 revolution-performance。

Skill 包含按任务选动作、三维对象与材质配方、Prefab 默认 override、按需发现和少往返、Undo/清理及边界。不安装参考工具的二进制，不改用户 Agent 的认证配置。

六参考工具与边界

参考强项是明确命令、可组合批量、工作流技能和广泛编辑器覆盖；这里采用设计思路，不整包复制。

本轮保留现有业务测试、AB/导表、运行时与 Player 能力，并补三维对象和材质/Shader两个高频操作域。没有为了“看起来一样强大”开放任意 C# 或 shell 执行，也没有把未验证功能写成完成。
