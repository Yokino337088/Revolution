〇它是干什么的

先花 30 秒建立直觉，再动手。

只记 1 件事就能干活（真的）

编辑器里跑得快，不代表真机不卡。所以"打包 → 启动 → 采样 → 判定"被拆成下面几步，每步都能被脚本和 AI 直接调。

# 1. 打一个性能测试包（IL2CPP、非开发包、带自动化开关）
py -3.13 Revolution.RevCLI/rev.py build player --target StandaloneWindows64 \
  --path D:/Builds/Game/20261031-01/Game.exe --backend il2cpp --automation --frame-timing

# 2. 启动它，并开一个 AI 能连进来的会话
py -3.13 Revolution.RevCLI/rev.py player launch --executable D:/Builds/Game/20261031-01/Game.exe \
  --directory D:/Evidence/Game/session-01 --port 18766

# 3. 让它采 10 秒帧数据，再按 runId 核对结果（见第五节）
#    runtime.performance.begin → state → cancel
人话 它 = 把"打个包、跑起来、量一下"这三件手工活变成接口。

构建与调度走 CLI / MCP；游戏内面板只是消费者——它读的是同一份运行时采样，不存在"面板显示 60 帧、报告写 55 帧"两套数。

BUILD构建真实包
IL2CPP + 非开发包，回执是真实 BuildReport
LAUNCH拉起独立进程
拿到 endpoint / pid / sessionId 等身份
SAMPLE有界采样
begin 只接单，state 才是结论
VERIFY按 runId 核对
completed + success + frames>0 + errors=0
它替你解决的问题怎么做的
编辑器 60 帧，真机掉到 30 帧只认真实图形 Player 的数据；Mono / Editor 成功不能当 IL2CPP 通过
手点 Build Settings 容易漏开关一条命令固定 development / automation / frameTiming 组合
"刚才那 10 秒到底多少帧"说不清begin 返回唯一 runId，结论按同一 runId 核
AI 抢了编辑器，工程被锁复用已有编辑器（live 模式），不另起第二个 Unity
跑完没人收尾，环境越来越脏finally 恢复构建设置 + 协作取消采样
适用范围先说清楚 本文针对 Unity 2022.3 + Windows x64。手机（Android）与 WebGL 只在第八节讲边界，不代表已经支持或验收。

一三步跑通（可粘贴）

Python 3.10+；已有编辑器用 live 模式，别开第二个 Unity 争用工程。

第 1 步 · 打性能验收包
耗时可能几分钟，客户端 timeout 要给够（示例 3600 秒）。
py -3.13 Revolution.RevCLI/rev.py --project D:/Game --mode live --timeout 3600 \
  build player --target StandaloneWindows64 \
  --path D:/Builds/Game/20261031-01/Game.exe \
  --backend il2cpp --automation --frame-timing
路径必须是专用空目录下的完整路径，每次换新的（20261031-01 → -02）。
第 2 步 · 启动并开会话
会话目录也每次用新的空目录。
py -3.13 Revolution.RevCLI/rev.py player launch \
  --executable D:/Builds/Game/20261031-01/Game.exe \
  --directory D:/Evidence/Game/session-01 --port 18766

# 想让 AI（MCP）连进去，把会话的 runtime.json 指给 MCP 服务
py -3.13 Revolution.RevMCP/rev_mcp.py \
  --runtime-endpoint D:/Evidence/Game/session-01/runtime.json \
  --reports D:/Evidence/Game/mcp serve
第 3 步 · 采样 + 收尾
先 begin 接单，再 state 核对，最后 finally 里 cancel / disable。
# 采 10 秒，预热 2 秒（参数上限：seconds 1~600，warmup 0~60）
{"target":"game","action":"runtime.performance.begin","arguments":{"seconds":10,"warmup":2}}

# 只读查询：用 status=completed 做有界等待，别 sleep 猜
{"target":"game","action":"runtime.performance.state","arguments":{}}

# 协作取消（保留 cancelled 状态），再关掉采样器释放 Recorder
{"target":"game","action":"runtime.performance.cancel","arguments":{}}
{"target":"game","action":"runtime.performance.disable","arguments":{}}
build player→ player launch→ performance.begin→ state 轮询→ finally 收尾
超时不等于"没构建" 构建超时后不要盲目重跑：构建可能已经发生。正确做法是读同一工单和 BuildReport，再决定下一步。

二两种包，别打错

同一套命令，两个开关组合，用途完全不同。

开发诊断包（自己排查用）

IL2CPP + development=true

关闭 Script Debugging / Deep Profiling / 自动连 Profiler。

要完整指标和功能回归时用它。

性能验收包（出报告用）

IL2CPP + development=false
+ automation=true + frameTiming=true

接近线上的性能表现，受控内部测试包，不是公开发行包。

REV_AUTOMATION 是"这一单的临时宏"，不是项目永久宏 本次构建通过 extraScriptingDefines 把 REV_AUTOMATION 加进去，不改项目永久宏。 但注意：项目自己的 GM、隔离接线、调试面板也必须允许 REV_AUTOMATION —— 只给框架加宏，并不会让项目里 UNITY_EDITOR 包起来的代码进 Player。
包类型开关用途
开发诊断development=true完整指标 + 功能回归（加 --development）
性能验收development=false / automation=true / frameTiming=true出性能报告、对接自动化断言
正式发行automation=false / development=false，且永久宏不含 REV_AUTOMATION对外发布
发行前要核对"能力真的不存在"，不能只把面板藏起来 面板隐藏 ≠ 自动化能力没了。发布检查要看实际能力是否已从包里消失（宏、注册入口、HTTP 桥）。

三让 AI / 命令行帮你打包

CLI 和 MCP 走同一条构建链，参数一一对应。

打包前先自检这 5 项

目标平台目标平台受支持，且与当前活动平台一致
IL2CPP 模块Windows IL2CPP 模块已装
C++ 工具链Visual C++ 工具链可用
场景启用场景配置正确
AB 资源真实 AssetBundle 已就绪
build.player 不负责生成 AB 项目构建管线必须在 Player 之前完成依赖校验和 AB 构建。另外：完成 ab.build 不等于资源已发布 —— 有些实例关掉了 AB 自动首包复制，打包前要核对 StreamingAssets 里真有文件。

参数速查

参数说明
--path专用空目录下的完整路径（含文件名）。允许工程外目录
--backendcurrent / mono / il2cpp；测性能一定要 il2cpp
--automation本次构建加 REV_AUTOMATION，开自动化桥
--frame-timing开帧时序统计（非开发包想拿 GPU 数据必须开）
--development只有打开发诊断包时才加
会被直接拒绝的路径 覆盖旧包 · 目录链接 · 工程内 Assets / Packages / ProjectSettings / Library / Temp。 重试时不要删用户旧包，另选新目录。

MCP 调用长这样

{
  "target": "editor",
  "action": "build.player",
  "arguments": {
    "target": "StandaloneWindows64",
    "path": "D:/Builds/Game/20261031-01/Game.exe",
    "backend": "il2cpp",
    "development": false,
    "automation": true,
    "frameTiming": true
  },
  "intent": "构建独立IL2CPP性能测试包"
}

怎么算"打包成功"

回执字段含义
result / errors / warnings只有 Succeeded 且 errors=0 才算成功
seconds / bytes真实耗时与产物大小
backend / buildId构建身份，报告里要和采样结果对上
rev-build.json写在产物旁边，含构建身份，不含凭据
设置会自动还原，但崩溃时不保证 backend、Frame Timing Stats、IL2CPP 编译配置都在 finally 里恢复。 编辑器崩溃时 finally 不保证执行 —— 继续之前先核对项目设置。
target 和活动平台不一致怎么办 先调 build.target 切换平台，等域重载完成再打 Player。别在重载中直接构建。

四启动 · 探活 · 收尾

一个会话 = 一个独立进程 + 一个空目录 + 一个端口。

# 启动
py -3.13 Revolution.RevCLI/rev.py player launch \
  --executable D:/Builds/Game/20261031-01/Game.exe \
  --directory D:/Evidence/Game/session-01 --port 18766

# 看状态
py -3.13 Revolution.RevCLI/rev.py player status --directory D:/Evidence/Game/session-01

# 退出
py -3.13 Revolution.RevCLI/rev.py player stop --directory D:/Evidence/Game/session-01
返回的身份用来干什么
endpointPathAI 连这个 Player 会话的入口
pid / sessionId进程与会话身份（对报告、对日志）
launchId / buildId这次启动跑的是哪个包，可追溯
token不返回（只在 runtime.json 里，属本机凭据）
runtime.json 含本机凭据 只放在被忽略的目录；不要入库，不要粘贴进报告或聊天记录。

能传什么、不能传什么

可以

--arguments 传 JSON 字符串数组，例如窗口宽高。

多实例：不同端口 + 不同会话目录。

不行

覆盖保留的自动化 / 日志参数。

用 batchmode / nographics 测渲染。

人话 launcher 首版只支持本机 Windows exe。

启动失败时只终止本次创建的子进程，不会误杀别人的进程。

stop 是"礼貌退出"，不是强杀 stop 通过校验过的 HTTP 会话调用 runtime.quit，不接收任意 PID 强杀。 stopped 只表示"已接受退出且运行时桥清掉了本次 endpoint"；进程最终退出仍需宿主观察 —— 崩溃不能当正常收尾。

AI 侧（MCP）怎么调

工具关键参数
rev_call target=cli
action=player.launch		executable / directory / 可选 port / arguments / timeout
player.status / player.stop只需要 directory
最容易犯的错：把 Editor 会话当成 Player 会话 启动后要用返回的 endpoint 建立独立 Player 的 MCP 会话。Editor 的 build.* / scene.* / game.perf.* 等 Editor 专用接口不会自动出现在 Player 里。

调用过程要能复盘

  1. 每次连接先 rev_discover：确认运行实例、能力、GM 列表。
  2. 再 rev_call 查 runtime.identity、业务状态、隔离状态。
  3. 用 rev_run 执行带 expect 和 finally 的计划。
  4. 向用户展示实际工具名、关键参数、目的、结果；没执行的步骤明确标"未执行"，不要把直接 CLI/Hub 调用冒充成 MCP 工具。
纪律 GM 用完整注册名和 discover 返回的参数 schema；运行时桥走的是玩家同一业务入口 —— 接受请求 ≠ 完成。编译 / 域重载 / 切换 Player 会话之后，重新 discover。

五采样 API（就这几个）

三层：开关 → 快照 → 有界测量。日常只需要认识后两个。

接口作用
RevRuntimeAutomation.EnablePerformance
↔ runtime.performance.enable		启动轻量采样
PerformanceSnapshot
↔ runtime.performance.snapshot		返回最近最多 2048 帧的窗口快照
RevRuntimeAutomation.DisablePerformance
↔ runtime.performance.disable		释放 Recorder
runtime.performance.begin接单：传入 seconds（1~600）与 warmup（0~60，默认 0），返回唯一 runId
runtime.performance.state只读查询，可用于有界 until
runtime.performance.cancel协作取消，保留 cancelled 状态
采样器不会偷偷改你的画质 它不改 VSync、不改帧率上限、不改分辨率、不改游戏难度。数据怎么来就是怎么来。
面板 建议每 0.5 秒读一次快照；面板关掉就停文字更新。正式测量期间请隐藏面板 —— 查询和面板本身有开销，要做"开 / 关"对照才干净。

标准一份计划（可直接挪去改）

{
  "name": "独立Player十秒采样",
  "steps": [
    {"target":"game","action":"runtime.identity","arguments":{},
     "expect":[{"path":"/data/editor","equals":false},
               {"path":"/data/backend","equals":"IL2CPP"}]},

    {"target":"game","action":"runtime.performance.begin","arguments":{"seconds":10,"warmup":2}},

    {"target":"game","action":"runtime.performance.state","arguments":{},
     "until":{"path":"/data/status","equals":"completed","timeoutSeconds":30,"intervalSeconds":1},
     "expect":[{"path":"/data/success","equals":true},
               {"path":"/data/errors","equals":0}]}
  ],
  "finally": [
    {"target":"game","action":"runtime.performance.cancel","arguments":{}},
    {"target":"game","action":"runtime.performance.disable","arguments":{}}
  ]
}

判定清单：这 6 条全过才算真跑完

1 同一 runId核对的是 begin 返回的那个，不是别的
2 status=completed不是 cancelled，也不是还在 running
3 success=true失败原因要去 errors 里找
4 frames>0一帧没采到等于没测
5 seconds 达标实际时长达到请求值
6 errors=0 且 cancelled=false最后再补业务负载与资源回收断言
这只是"采样链路"示例，不是完整验收 正式计划要在它之前接项目隔离与固定负载，在 finally 里接项目回首页 / 复位。 截图和 GIF 在计时窗口之外采集。

六指标怎么读

每个数字都有明确口径，别自己发明算法。

FPS

口径 FPS = 窗口帧数 ÷ 墙钟秒。

同时保留 P50 / P95 / P99 / max，以及超过 12.5ms / 16.67ms / 33.33ms 的帧占比 —— 平均值好看不代表不卡。

CPU、渲染线程、GPU 是并行的，不能相加 也不要在整帧耗时里扣掉 EditorLoop 去算"真实 FPS"。那是两套东西。

渲染计数

指标说明
Draw Calls / Total Batches / SetPass来自 ProfilerRecorder
三角形 / 顶点同上；每项带 available / value / unit
动态 / 静态合批 / Instancing 明细Release 包里可能不可用，别当 0 看
缺样本是 -1，不是 0 0 是"采到了且真的为 0"，-1 是"没采到"。主 / 渲染线程的纳秒已换算成毫秒；内存字段单位是字节，且不是进程全部内存。
"GC Allocated In Frame = 0"要谨慎 没有有效性探针时，这个 0 不能用来承诺"全局零 GC"。

GPU 数据

规则 只接收新时间戳且值为正的 FrameTiming，记录 gpuSamples；没有有效样本保持 -1。 非开发包必须启用 Frame Timing Stats（构建时 --frame-timing 就是干这个的）。

每次结果必须一起记的环境信息

构建身份buildId、backend
设备与接口设备 / 图形 API
显示分辨率、窗口焦点
限制VSync、帧率上限
失焦帧数unfocusedFrames 非 0 必须单独分析
结论口径后台样本不能混进前台样本当"优化收益"

采样窗口的硬约束

  • 固定测量每秒预留 1000 帧容量；超过容量明确失败，不截断。
  • 采样循环内不排序、不写 CSV / JSON、不录 Profiler。
  • 汇总只在窗口之外做，避免把统计开销算进被测帧。

七新手最容易踩的 6 个坑

每一条都对应一个真实故障。

1. 拿 Mono 或 Editor 的成绩当 IL2CPP 通过 IL2CPP 会裁剪代码。实包必须验证：裁剪后功能还在、中文参数正常、JSON 能序列化、截图能出、跨场景注册没丢。Windows IL2CPP 必须用真包验证。
2. 在同一个输出目录反复打包 覆盖旧包会被直接拒绝，重试也别删旧包（那可能是上一轮的证据）。每次新建一个带日期序号的目录。
3. 以为 begin 返回了就是测完了 begin 只接受作业。必须回到 state 核对同一个 runId 的状态与数据，再做业务断言。
4. 把 -1 当成 0，把"不可用"当成"没问题" 缺样本是 -1；Release 包里部分合批明细本来就不可用。报告里要写"无数据"，不能写"0"。
5. 用 batchmode / nographics 测渲染性能 这样测出来的不是真机画面。要用真实图形 Player，固定分辨率、画质、输入与资源。
6. 把 runtime.json 提交或贴进报告 它含本机凭据（token / endpoint）。只放被忽略目录，未执行与失败的步骤照实记录，但凭据不外泄。

八谁负责什么 + 平台边界

框架只做通用能力，业务的事别塞进来。

框架负责项目负责
构建 · 运行时桥
进程与会话身份
通用计数器
有界测量 		存档隔离
真实业务造局
规则断言
UI / 资源预算
正式流程清理
边界纪律 不要把项目的 GameFlow 或 81 棋夹具搬进框架。框架给的是管道，不是某个项目的玩法。

平台边界

平台现状
Windows x64主战场。Player HTTP 走 127.0.0.1 + 随机 token + session，业务在主线程执行
Android需另验：HTTP 支持、安装启动、端口转发。尚未验收
WebGL没有这条 HttpListener 通道，不适用

真机验收的最低要求

  • 必须是真实图形 Player，固定输入、画质与资源。
  • 开发包 / 非开发包分开报；冷启动 / 稳态 / 热态分开报；规则通过 / 性能预算分开报。
  • 报告保留全部轮次、取消和失败原因，不许只留好看的那次。
  • RevGame 不生成 ZIP、不导出 Profiler 录制或内存快照；机器证据放 .codex/work。

九这次接入踩到的 6 个问题

写在这不是为了记功，是为了你下次别再踩。

① 长 AB 构建后，回执比心跳先到
症状：连续计划里下一步误判"桥离线"。

现在 RevClient 对仍打开的编辑器做最多 15 秒的有界等待恢复心跳；等待期间不创建、不重发工单，也不会另起一个 batch Unity。

② 构建后设置只恢复在内存里
症状：构建结束、Unity 一重启，PlayerSettings 又变回去了。

BuildPipeline 会保存临时 PlayerSettings，finally 恢复内存值之后还需要 SaveAssets 落盘。默认值可能被序列化成显式字典项，语义与原设置一致。

③ 字体材质被误判
症状：构建校验报错，或字体在包里变成方块。

字体导入器生成的 Font.material 与普通业务材质要区别对待：校验只认同一个 Font 资产实际持有、并使用 GUI/Text Shader 的材质。不能把 Editor 里 HideAndDontSave 的对象手工塞进 Always Included；项目自定义材质仍须满足原 Shader 门禁。

④ 总批次计数器的名字不一样
症状：采样里总批次一直 N/A。

Unity 2022.3 Player 里原生标记可能叫 Batches Count。采样器支持这个明确别名；两种名字都缺失时仍然报 N/A（不会编一个数）。

⑤ ab.build 完成 ≠ 资源已发布
症状：包构建成功，进游戏发现资源缺失。

有些实例关掉了 AB 自动首包复制，所以 Player 构建前必须由项目管线发布并核对 StreamingAssets 里的真实文件。

⑥ VS2026 被识别成 UNKNOWN
症状：vswhere 能看到 VC 组件，但 IL2CPP 编译失败。

本机 VS2026 在 Unity 2022.3.15f1c1 下被识别为 UNKNOWN。vswhere 发现 VC 组件不等于 IL2CPP 可用，要真的 BuildReport 成功才算。
